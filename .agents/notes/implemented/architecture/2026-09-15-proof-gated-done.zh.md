# Agent Note: 证明闸门化的完成定义与独立评审

Status: implemented

[English](2026-09-15-proof-gated-done.md) | 中文

## 问题

"'完成'意味着被证明"曾是框架宣称却并未强制的法则。`set_definition_of_done` 的 `prove` 动作从执行该工作的同一个代理那里接收一段自由文本 `evidence`，并据此把契约推进到 `proven`；没有任何东西运行、检查或独立确认过什么。多任务策略在上一层犯了同样的错误，指示主导者"评判合并结果"——由分派工作的那个代理来评判它。

其结果是：这款产品最具区分度的主张——结论——只以一个词的形式存在。会话可以自我认证，而读者无法分辨一条由通过的测试套件了结的契约，与一条由代理的乐观了结的契约。

## 决策

`prove` 只接受第三方可复核的证据，且撰写者绝不是评审者。

**两条证明路径，均为持久化。** `receipt` 指名本会话中某次调用的 `tool_call_id`，且其记录结果不是错误；解析过程遍历会话自身的事件日志，找到该 `tool/call` 及其最后一条 `tool/result`，并从记录的块上读取 `isError`。`countersign` 指名新包 `@saturnai/dsh-review` 在独立评审给出 PASS 后签发的令牌；解析过程遍历日志找到 `done/countersign` 记录，并同时检查结论与被评审的那条确切陈述。仅有自由文本会被拒绝，并同时列明两条路径。

**评审者在结构上是独立的。** `review_definition_of_done` 以 "Mars — adversarial reviewer" 角色运行一次性子代理，并将 `outputSchema` 设为评分量表，因此接缝会在本包看到答案之前完成校验。`inheritsParentContext` 为真的提供方会在调用处被拒绝：分叉出来的评审者会继承它本应评判的那套推理。契约工具在评审者的作用域内被禁用，因此它既不能证明该契约，也不能为自己再叫一次评审。每一次结论都被记录，而不只是通过的那些，因此会话无法反复重掷评审直到出现绿灯。

**持久词汇与日志同在，而不与评审者同在。** `ReviewVerdict`、`ReviewCriterion`、`ReviewScore`、`CountersignRecord` 与 `DoneProof` 声明在 `@saturnai/dsh-done/types` 中，而该模块自陈的职责正是投影键及其所承载的持久载荷词汇。`@saturnai/dsh-review` 依赖 `done`，并通过其导出的 `mintCountersign` 签发令牌；依赖边单向，`done` 在没有评审者参与编排时依然可用，而 `ui-done` 只读一个投影就能同时绘出状态与量表。

**人类保留一条路径，并且被如实标注。** `/done prove <evidence>` 仍然接受本人的确认——工作的所有者是当事人，而不是自我评分的执行者——并记录为 `{ kind: 'human' }`，因此标签显示"由你确认"，而不是暗示有机器复核过什么。

## 备选方案

- **用服务接缝（`ctx.doneReview`）做校验**——否决：会签必须在恢复与分叉后依然有效，因此它属于会话日志；而由日志解析的令牌根本不需要服务。
- **把量表类型声明在评审包里**——否决：那样 `done` 为了折叠自己的投影就得依赖 `review`，依赖边反转，契约在没有评审者时将不可用。
- **在 `/done` 命令处也拒绝自由文本**——否决：那会破坏标签上的证明按钮，并错误归类系统中唯一有资格作出确认的当事人。如实标注该确认才是诚实的形式。
- **要求回执必须指名"类测试"工具**——否决，因为这是无法强制的臆测；闸门证明某次调用运行过且未报错，指引要求提供一次真实运行，而 README 直言评审路径才是强路径。

## 后果

`done` 投影升至 `stateVersion: 2`：已证明的契约必须携带它的 `proof`，因此记录了无证明来源 `proven` 的 v1 快照不再折叠——按照本仓库对持久格式的预发布立场，这是可以接受的。没有评审者的编排仍保留一条可用的证明路径，即回执。有评审者的编排则为每次评审付出一次子代理的模型请求，且计入评审者自己的上下文而非调用者的上下文。

界面随机制一同改变：标签在状态旁携带来源信息，已会签的契约会展开评审者的完整量表作为结论卡片——盖章的结论、评审者、总结，以及每项标准一行的分数。多任务策略如今明说了它此前违反的那条规则：协调者从不评判自己团队的工作。

证据：`packages/saturn/review/tests/composition.spec.ts` 在脚本化的模拟模型背后，通过 Loader 从 `cordis.yml` 启动整套编排，并走完法则的端到端流程——仅有文本的证明被拒绝、指名一次真实未报错工具调用的回执把契约翻转为已证明、以及全新评审者给出的 REVISE 结论让修改后的契约保持已声明。
