# Agent Note: 定义完成记录迁入 Session 头部芯片

Status: implemented

[English](2026-09-15-definition-of-done-header-chip.md) | 中文

## 问题

定义完成（definition of done）记录此前占据 composer 上下文栈中的 `conversation.input.dock` 列表，始终显示在输入框上方：固定高度的契约行、轮次回执行与检查点行。读者只在两个时刻查看该记录——陈述工作时，以及提交证据时——因此这条常驻条带把 composer 高度和正文宽度花在读者并未阅读的装饰上，并与真正作用于下一次输入的 todo、goal、queue 面板并排。用户反馈该条带具有侵入性。

## 决策

`packages/client/ui-done` 注册到 `conversation.session.header.utilities`，即 Conversation 头部右对齐的 Session 实用工具列表。该坑位以 `session` 作用域、`list` 种类声明，并由头部组件渲染，因此这次迁移无需修改 `ui-conversation`，也不新增坑位；注册保持原有的 `order: 5`，位于头部自身控件之后。关于工作的 Session 读数属于头部，不属于 composer 的上下文栈。

芯片是尺寸对齐头部自身控件的一行省略文本——最小高度 28px、12px 字号、上限 46ch——承载状态环、`STATED` 或 `PROVEN` 标签、语句、证明后的证据，以及一个折叠箭头。宽度低于 720px 时语句行隐去，状态环、标签与箭头保留，因此头部在窄窗口下不会增高。既无契约也无检查点的 Session 不渲染任何芯片；只有检查点的 Session 保留该位置并显示检查点标题。

点击芯片打开承载完整记录的浮层：语句及其证据、行内编辑器、三个动词（prove、edit、clear）、轮次回执与检查点行。该浮层通过 portal 挂载到 `document.body`，并经 `useAnchoredPosition` 相对芯片定位，因此头部自身的裁切与层叠都无法切掉它；它是宽度 380px 的表面，并被约束在视口宽度内。关闭方式为外部指针按下、Escape 或再次点击芯片，Escape 会把焦点交还芯片。编辑器打开期间 Escape 归编辑器所有，因为此时关闭浮层会丢弃正在修改的语句。

该浮层采用 `packages/client/ui-theme` 拥有的共享玻璃材质——`--dsw-glass-surface`、`--dsw-glass-filter` 与 `--dsw-glass-elevation`，在主题样式表中一次性声明，并带有降低透明度与不支持 backdrop-filter 时的回退（[Web 客户端样式](../../../../docs/web-styling.zh.md)）——同时 CSS Module 为每个 token 传入玻璃材质之前的回退值，因此在缺少玻璃样式表的环境中该浮层仍然是一个表面。`react-dom` 与 `@types/react-dom` 加入 `devDependencies`，与其他使用 portal 的客户端包保持一致。

## 测试

`tests/turn-receipt.client.spec.tsx` 直接驱动芯片及其浮层：既无契约也无检查点的 Session 不渲染任何内容，一次点击把单行芯片换成完整记录，浮层中的回执将契约的判定与该轮次发布的路径合并，Escape 关闭浮层并把焦点交还芯片，打开中的编辑器独占 Escape，外部指针按下会关闭浮层，三个动词都到达注入的命令调用，被拒绝的动词会显示其失败行。同一文件保留回执自身的用例：陈述态的契约、已证明却不携带证据的契约，以及能力缺失，三者都判定为 `NOT_ASSESSED`，浮层直接陈述这一点，而不会暗示该轮次没有改动。

## 曾考虑的替代方案

**保留在 composer dock 中并瘦身。** 更短的契约行会削减纵向占用，同时让面板继续留在输入框前方，也复用了已接好的缝隙。不予采纳，因为反馈针对的是位置而非高度：该记录仍被读作 composer 的一部分，而回执与检查点行除了放进一个不许增高的条带内部的滚动区域之外，无处可去。

**在 transcript 顶部固定一条条带。** 会话上方的条带既不会撑高 composer，也不会被滚动带走。该处没有坑位，因此意味着要向共享的 `ui-conversation` 包新增一个坑位——为头部本已提供的 Session 读数，对一个拥有 transcript 的包做大范围改动。

**用模态对话框代替浮层。** 模态无需 portal 即可脱离头部裁切，也能在不受尺寸约束的情况下承载完整记录。但它同时夺走界面其余部分，对读者在会话旁边查阅的记录而言仪式过重；锚定浮层在记录打开时仍保持 transcript 可读。

**让轮次回执与检查点行始终可见。** 回执携带当前轮次产生的路径，检查点是该 Session 的还原点——是读者可能想免点击查看的两半。把它们留在头部会使常驻表面高于它所替换的条带，而这正是本次改动要消除的性质。

## 后果

composer 的上下文栈只保留作用于下一次输入的面板，契约、其判定与回执则作为关于该 Session 的常驻读数留在头部。记录从常驻屏幕变为一键可达：读者未打开浮层时看到的，是一行省略语句，其 `title` 承载完整语句与证据。

芯片按头部自身控件定尺寸，而非按记录定尺寸，因此长语句既不会撑宽工具条，也不会让其换行。浮层绘制在头部盒模型之外，这正是解除裁切约束的原因，代价是引入 portal：组件现在依赖 `react-dom`，其测试必须提供真实的 `document.body`。浮层关闭有三条路径（外部指针、Escape 与芯片），其中编辑器打开时 Escape 交给编辑器，使一次按键不会丢弃正在编写的语句。
