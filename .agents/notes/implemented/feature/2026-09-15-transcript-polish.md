# Agent Note: transcript polish — prose measure, fence wrap, motion tokens, verb-first tool titles, ring tilt

Status: implemented

English | [中文](2026-09-15-transcript-polish.zh.md)

## Problem

`recon/desktop-ux-audit.md` cross-checked four prior 2026-09-14 docs against the code as of this session and found five of seven concrete, file:line-cited defects still open a full day of commits later — the transcript itself ("a plain dark chat log — could be any AI coding CLI's web view") carried the highest-leverage findings: unbounded prose measure (77–110 characters per line, median ≈100), code fences that word-wrap mid-token in a coding tool, 14 ad hoc motion durations with no named system, tool-row titles that are bare nouns ("Bash", "Read", not a considered verb), a live `Inter` font-family fallback (the design law's own explicit banned tell), and two render paths drawing the signature ring at two different tilt angles (-18° vs ≈-14.3°).

## Decision

Six independent fixes, each with its own acceptance test:

1. **Prose measure.** `ConversationRoot.module.css`'s `.root` declares `--dsh-chat-prose-measure: 70ch`, a new axis kept deliberately separate from the existing `--dsh-chat-content-width` (which keeps sizing the outer column, the composer, and tool cards). `MarkdownText.module.css` applies it to `.markdown :where(p, li, blockquote, h1..h6)` — the textual-flow elements only, not the `.markdown` container itself, because a block child cannot render wider than its parent's containing block: capping the container would have squeezed code fences and tables down with it. Targeting the elements directly needs no explicit exemption list.
2. **Fence wrap policy.** `CodeBlock.module.css`'s `.block :where(pre)` changes `white-space: pre-wrap; word-break: break-all` to `white-space: pre` (keeping the existing `overflow-x: auto`), matching the sibling `TerminalBlock`/`DiffBlock`/`ReadBlock`/`SearchBlock` primitives it previously contradicted. No inline `word-break` override existed in `CodeBlock.tsx` to remove (the SPEC anticipated one; none was found).
3. **Motion tokens.** `ui-theme/src/styles/base.css`'s `:root` declares `--saturn-dur-1/2/3` (120/200/320ms) and `--saturn-ease-standard/out/exit`, alongside (not replacing) the existing single-value `--saturn-duration`/`--saturn-ease` pair that `ui-skin-saturn` owns in its palette scope. Ten call sites now use them: five are real migrations (the `.markdown a` focus-ring transition, and four `opacity` hover/reveal transitions across `ToolRow.module.css` and `bash-sample.module.css`, both previously hardcoded at `100ms ease`); five are new, narrowly-scoped additions tied to a real, pre-existing state change — the new per-row duration's entrance (a "receipt arriving" beat, both `ToolRow.module.css` and `bash-sample.module.css`), the file-path link's hover color, and the queue editor's focus border-color plus its action buttons' hover/disabled transitions. The two long ambient sweep loops (`dsh-tool-row-sweep`/`dsh-bash-row-sweep`, 2.6s) are left alone — a different motion category (continuous ambient, not a discrete named-token transition) that the token scale was never meant to cover.
4. **Verb-first tool titles + duration.** `toolRowModel` now resolves a variant's title key against the row's state (`running` vs settled) through a `{running, done}` pair, scoped deliberately to the three tools the audit named: Bash ("Running…" / "Ran"), Read ("Reading file…" / "Read file"), and Grep ("Searching…" / "Searched", handled in `SearchRow` since grep already owns a name-specific title override). Every other variant (write/edit/code/glob/pwsh/the cordis lifecycle verbs) keeps its existing single label unchanged — an intentional scope decision, not an oversight; see Deviations. `ToolRowModel` also gains `durationMs` (`time - callTime`, null while running or when the paired call fell outside the loaded window) and every `ToolRow`/`BashRow` call site now passes it through; `ToolRow` renders it as a settled receipt between the title and the summary separator, matching the message footer's "Ran for Xs" style, with its own short entrance animation (item 3).
5. **Dead `Inter` fallback.** `QueueDock.module.css`'s two `font-family: Inter, var(--dsw-font-family)` declarations become `font-family: var(--dsw-font-family)` — a confirmed `ai-slop` hit, the design law's own explicitly banned typeface, harmless only because no `@font-face` for it ships anywhere in `packages/client`.
6. **Ring tilt.** `orbital-field.ts`'s live canvas now rotates at a named `RING_TILT_RADIANS = -18°` (was `-0.25` rad ≈ -14.3°) instead of a bare magic number, and `OrbitalCanvas.tsx`'s static SVG fallback (already at -18°) is annotated to say so explicitly. One tilt value everywhere, per SPEC §2.

## Consequences

The transcript now caps prose at 70ch instead of the audited 77–110-character lines, code fences scroll instead of wrapping mid-token, every discrete transition in the touched files reads off one of six named tokens instead of a bare number, three tool-row titles read as verbs with a visible per-row duration, the banned `Inter` fallback is gone project-wide, and the signature ring draws at one tilt everywhere. The trade-offs: `--dsh-chat-prose-measure` is a new, separate custom property from `--dsh-chat-content-width` (two axes to keep straight, not one) and — after the fix round below — needs an explicit `none` reset wherever `MarkdownText` renders outside the assistant transcript, so every future consumer of `MarkdownText` must remember to reset it or inherit the 70ch fallback unintentionally; verb-first titles and per-row durations are scoped to three tools plus a generic duration render, so the copy is uneven across tool variants until a follow-up widens it (see Known follow-up); and the two ambient sweep animations were deliberately left outside the new motion-token system as a different animation category.

## Deviations from the SPEC text (declared, not silent)

- **Verb-first scope.** SPEC §3 C2 and the audit both name exactly three worked examples (Bash/Read/Grep); every other tool-row variant was left with its existing single label rather than inventing new present/past copy the SPEC never specified wording for. Widening this to write/edit/code/glob/pwsh/webSearch/webFetch is a natural follow-up but was out of this session's reviewed scope — see Known follow-up.
- **Duration reaches every row, not only the three retitled ones.** The per-row duration is generic (any settled call with a `callTime`), including todo/ask-question rows and the cordis lifecycle actions — broader than the three named examples, but it directly serves the audit's own "per-row duration beside the state dot" wording without a variant-scoped carve-out, and several pre-existing baseline tests needed their concatenated-text assertions updated to include it (see Testing).
- **`AssistantMarkdown.module.css` has no `.markdown` rule.** SPEC §3 C2 names `AssistantMarkdown.module.css`'s `.markdown` rule as where the prose-measure cap should land; that rule does not exist there — the actual markdown-prose root class (rendered by `MarkdownText`, `ui-primitives/src/markdown/**`, already in this cell's IN scope) is where `.markdown` is defined and where the assistant's rendered prose actually lives. Applied there instead; `AssistantMarkdown.module.css` itself needed no change.
- **Pre-existing baseline test edits.** `packages/client/ui-tool/tests/**` is fully in this cell's IN scope, so the handful of pre-existing assertions that hard-coded the old bare-noun titles (and predated any duration text) were updated alongside the feature, in a separate `fix(saturn):` commit after the initial `feat(saturn):` commit — never inside the RED test files this cell authored fresh. Listed in Testing.

## Alternatives considered

**Cap `.markdown`'s own `max-width` and add an explicit breakout for `pre`/tables (the pattern the codebase already uses for wide tables via `md-table-wide`).** Rejected: the breakout technique (negative margin + width calc) exists because that specific rule needs to escape a narrower ancestor. Here, simply not constraining the ancestor at all and capping only the text-flow children is strictly simpler and produces the same visible result with no negative-margin arithmetic to maintain.

**Give every classified tool variant a present/past pair up front.** Rejected for this pass: SPEC and the audit gave exact copy for three tools only; inventing wording for the rest risks a copy choice nobody reviewed. Flagged as follow-up instead.

## Fix round (Mars review, REVISE, 2026-09-15)

A fresh-context Mars review of the six-item build above returned REVISE (not REJECT — all six DELIVER items were independently confirmed present and correct, and the test-tamper check on the original two commits was clean) with three required fixes, all inside this cell's IN scope:

1. **The Inter guard missed a substring.** `no-inter-font.client.spec.ts` uses `/\binter\b/i` (word-boundary), which never matches "Inter" embedded inside a larger word — exactly the case at `AssistantMarkdown.module.css:52`'s `/* Interrupted-turn terminal marker... */` comment. Reworded the comment to "Halted-turn terminal marker" (no behavior change, comment only) and added a new guard, `no-inter-substring.client.spec.ts`, that matches the SPEC §3 C2 ACCEPTANCE line literally — a plain, case-sensitive substring search for `Inter` (no word boundary), the same case `grep "Inter"` matches with no `-i` flag — so a future capitalized "Inter" anywhere, comment or code, cannot slip back in. (The new guard's first draft used a case-*insensitive* match, which is broader than the SPEC's plain grep and false-failed on ordinary words like "interactive"/"internal" elsewhere in `packages/client`; corrected before the RED commit's test files were built on, not a weakened requirement — see Deviations below.) `grep -rn "Inter" packages/client --include=*.css` now returns nothing.
2. **The 70ch prose-measure cap leaked into tool cards.** `MarkdownText.module.css`'s pinned rule (`.markdown :where(p, li, blockquote, h1..h6) { max-width: var(--dsh-chat-prose-measure, 70ch) }`) falls back to 70ch wherever nothing sets the custom property — which includes the same `MarkdownText` rendered inside a tool card's `WebBlock` (a web-search answer, `ToolRow.tsx:298` → `.webBody`, `ToolDetails.tsx:57` → `.web`, `WebBlock.tsx:156`), contradicting DELIVER (1)'s "tool cards exempt". Rather than widen the pinned `MarkdownText.module.css` rule the original RED test asserts verbatim (which would have required editing that RED test file), the fix declares `--dsh-chat-prose-measure: none` on `ToolRow.module.css`'s `.webBody` and `ToolDetails.module.css`'s `.web` — the exact wrapper classes `WebBlock` already receives as `className`. A *set* custom property (even to `none`) short-circuits the `var()` fallback, so this confines the cap to assistant transcript prose without touching the pinned assertion at all. New guard: `web-card-prose-measure.client.spec.ts`.
3. **The new duration entrance animation had no reduced-motion guard.** SPEC §2 binds "reduced-motion contract in CSS... everywhere"; `ToolRow.module.css` and `bash-sample.module.css`'s `.duration { animation: dsh-tool-duration-in ... }` (added by this cell) shipped without a `@media (prefers-reduced-motion: reduce)` block, unlike every sibling package with a CSS transition/animation (e.g. `ReasoningRow.module.css`'s own sweep guard). Added the matching guard block to both files, pinned by a new `tool-duration-reduced-motion.client.spec.ts`.

**Out of scope, reported not fixed.** Mars's finding on item 2 also names `MarkdownText` render sites in `ui-saturnbot/History.tsx`, `ui-trajectory/TrajectoryTable.tsx`, and `ui-user-questions/{PlanReviewPanel,QuestionComposer}.tsx` — all outside this cell's IN list (owned by other cells' packages). Each needs the same `--dsh-chat-prose-measure: none` declared on whatever wrapper class it already passes down to `MarkdownText`; flagged to the orchestrator as `integration_needs` rather than applied here. Mars also separately confirmed (not a required fix) that the pre-existing `dsh-tool-row-sweep`/`dsh-bash-row-sweep` ambient sweep animations (predating this cell, not part of any C2 DELIVER item) likewise carry no reduced-motion guard — left alone as out of this fix round's scope; noted here as a candidate for a future pass.

## Deviations (fix round)

- **Corrected the Inter guard's case-sensitivity before it was ever relied on.** The RED commit for this fix round briefly contained a case-*insensitive* `/inter/i` version of the new substring guard; running it immediately surfaced dozens of unrelated false-positive hits (ordinary words like "interactive"). This was corrected to the case-sensitive literal-substring check the SPEC's own grep performs *before* the implementation commit and before any pass/fail decision was made in reliance on the wrong version — not a weakening of a real requirement, and not an edit made to dodge a genuine failure. Declared here per the "wrong committed test → stop and say so" rule rather than silently folded in.
