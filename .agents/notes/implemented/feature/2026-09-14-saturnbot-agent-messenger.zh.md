# Agent Note：SaturnBot 通过独立智能体消息界面运行

Status: implemented

[English](2026-09-14-saturnbot-agent-messenger.md) | 中文

## 问题

SaturnBot 需要清晰的管理界面，处理持久专家对话、定时工作、准确审批和持久结果。替换主应用或展示虚构仪表盘统计会掩盖真实执行模型。

## 决策

新增 shell-overlay Client 插件 `ui-saturnbot`。主应用提供克制的右上角启动按钮；同源命名窗口包含三栏角色列表、角色对话和执行检查器。被覆盖的主应用设为 inert。Host 和桌面包负责 Remote 方法与原生弹出窗口许可。

通过私有且不依赖 React 的快照控制器和注入的插槽钩子使用生成的 Remote。串行执行命令与刷新，共享初始请求，失败时保留草稿，忽略销毁后的结果，并将命令接纳与轨迹读取失败分开。最多分五页加载最近 1,000 条日志，使重新打开的旧实例立即显示当前活动。仅轮询可见活动工作，并在启用的计划边界进行一次唤醒。

仅显示已记录分支、消息、工具输入输出、审批决定、暂存版本、报告、记忆、工单、webhook 和连接配置。明确的初始化及专家设置写入经 Host 验证的配置。拓扑画布仅在对应分支运行时移动；静态状态文字、减少动态效果、可见性暂停、密度与帧率限制以及资源清理均为必需行为。

## 考虑过的替代方案

**通用指标仪表盘。** 不符合用户提供的智能体消息界面参考，并会重复执行信息而无法帮助操作员行动。

**主对话中的模态框。** 用户明确要求独立管理窗口；模态框也会与常驻输入区争夺空间。

**组件内独立轮询。** 会导致重叠请求、过期状态和资源泄漏。控制器管理唯一可观察状态及全部传输时序。

## 结果

应用提供精致的智能体运营界面，并保留现有插槽组合架构。它管理一个工作区实例，而非多租户服务账户。界面如实标注有界近期轨迹及未配置连接。本地草稿在命令失败后保留，但关闭窗口后不保留。英文与简体中文文案由本包维护。

## 验证

专项测试覆盖角色独立草稿、发送成功与失败、忙碌接纳规则、准确审批载荷、最新优先简报、真实记忆记录、串行及共享传输、五页历史追赶、后台调度与销毁、启动按钮及 inert 和标题行为、画布生命周期，以及选定智能体消息快照。Client TypeScript 和本包 lint 通过；全局 UI 国际化检查仍有其他包的现有问题，但本包没有问题。完整应用提供最终浏览器及原生冒烟检查。
