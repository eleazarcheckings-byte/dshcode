# Agent Note: 基于权威工作状态的 Team 协作控制台

Status: implemented

[English](2026-09-14-saturn-mission-control.md) | 中文

## 问题

当 Team 成员列表、任务依赖和任务编辑位于狭窄的标题栏弹出框时，用户难以监督并行工作。与运行时事实没有明确关系的动画会让空闲的 agent（智能体）看起来仍在活动，隐藏的动画也会占用本应服务于实际工作的资源。

## 决策

Team 标题栏操作打开响应式协作控制台对话框。其画布为每位成员提供稳定的位置，将 lead 放在中心，并仅显示真实的成员关系和已分配任务之间尚未解决的依赖连线。节点数字统计已分配的未完成任务；沿圆周移动的指示点标记运行中的成员。悬停和键盘焦点把图示与普通成员导航按钮联系起来。旁边的任务看板提供精确完成数量，并按未完成、需要关注和已结束的工作筛选。

画布是无障碍成员列表和任务说明的增强展示。它在一个 React effect 内管理动画帧、尺寸观察器、相交观察器和可见性监听器。减少动态效果、文档隐藏、画布离屏和卸载都会停止帧循环。小屏幕显示完整的 HTML 控件，不显示图示。空闲和未运行成员使用中性状态点，而非完成指示。

Team Remote 保持任务状态的权威。打开、观察到成员运行状态变化、返回窗口、显式刷新和任务修改时会刷新；待处理编辑保留现有修订号检查和刷新代次。UI 说明刷新行为并保留手动刷新，因为一元 Remote 不向浏览器交付任务变更事件。

输入框下方的 Fleet 提供精确活动和关注事项计数，初始显示三条路线，并提供显式展开控件。它保持关注事项优先排序，并使用现有的寻址 subagent 导航路径。

## 考虑过的替代方案

**始终运行的轨道氛围动画。** 持续移动会让已停止的团队显得繁忙，并在离屏时消耗渲染时间。动画因此绑定运行状态，并在不可见时暂停。

**估算 agent 完成百分比。** 运行时提供任务生命周期状态，而非剩余工作量。因此概览以无障碍进度元素显示已完成任务数量，不给未完成任务部分完成值。

**自动定期轮询任务。** 当前浏览器 Team API 是一元调用，固定轮询频率会引入后台请求和刷新竞争。现有会话活动和可见性事件提供有效刷新时机，显式刷新操作则覆盖不影响成员运行状态的任务变更。当运行时拥有适当的浏览器观察 API 后，可以用它替代此限制。

## 后果

用户可以在一个对话框中检查工作归属、依赖、关注事项和精确任务完成情况。模态框保持键盘焦点，并在关闭时将焦点返回触发按钮。画布视觉始终依据成员列表和任务看板，但大型团队的详细检查仍使用文本成员列表。仅任务发生变化时可能需要手动刷新。客户端不增加持久事件、provider 能力、模型输入或部署配置。

## 验证

针对性 Team 和 Fleet 套件覆盖任务修订竞争、精确计数、看板筛选、成员导航、依赖去重、稳定布局、模态框焦点和 Escape 行为、可见性刷新、紧凑成员列表展开、动画暂停和观察器清理。应用构建和 Web 回放套件负责验证组合后的浏览器。
