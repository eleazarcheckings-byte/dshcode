# Agent Note：运行中 Harness 的远程访问

Status: implemented

[English](2026-09-15-saturn-remote-access.md) | 中文

## 问题

Harness 是一个本地主机。而人离开工位时，真正需要从它那里得到的东西——“这条命令可以执行吗”的答复、一次判定、一支忽然安静下来的编队——恰恰在人不在工位时到达。每一种显而易见的补救方案，都会把产品推向它不该去的地方：一个中继服务、一个账号、一份放在别人机房里的会话副本，或者一套与桌面窗口已有机制并存的第二套鉴权系统。

## 决策

在回环 Web 服务器旁边增加一个监听，只有完成过一次配对的设备可以访问，并把该设备的流量代理进既有服务器，**穿着桌面窗口已经持有的那一份会话**。浏览器鉴权仍完全归 `client-connection` 所有：边缘监听对 `http://127.0.0.1:<回环端口>` 执行一次它的启动令牌交换，并且只把所得的、绑定 authority 的 Cookie 保存在内存中。Harness 的鉴权没有任何一处被重新实现，设备也永远看不到那份 Cookie——每个被代理响应中的上游 `Set-Cookie` 都会被剥离。

设备自身的凭据是独立且狭窄的。配对令牌在内存中存活十分钟，只能使用一次，并在监听关闭时立即丢弃。兑换它会得到一个设备令牌，该令牌仅以 SHA-256 摘要形式存储、以常量时间比较，并可从设置或另一台已配对设备处吊销。由于 WebView 无法为文档随后发起的子资源请求附加 `Authorization` 请求头，通过鉴权的请求还会把同一凭据以 `HttpOnly` Cookie 的形式写回；配对响应会给出该 Cookie 的名称，以便伴侣应用知晓它是什么。

局域网模式自行铸造证书，并把 SHA-256 写入配对载荷供手机固定。隧道模式启动用户自行安装的 `cloudflared`，并把边缘监听绑定在回环地址，使隧道成为唯一入口。默认关闭；每一次状态变更都记入日志；日志中不含任何令牌、密钥或证书。

## 备选方案

**把既有 Web 服务器绑定到 `0.0.0.0` 并加一个密码。** 那是在 `client-connection` 已拥有的机制之外再立一套鉴权，与应用共用同一个端口，而且无法在不锁死全部设备的前提下单独吊销一台。

**把桌面的启动令牌 URL 分享给手机。** 它确实能用，同时也把一份永久、不可吊销、无法归属的凭据交给了任何能读到那张二维码的东西。

**自建中继或托管隧道。** 既产生持续成本，又在会话路径上插入第三方。隧道模式确实存在，但用的是**用户自己的** cloudflared：Harness 在 `PATH` 中查找，找不到就以 `tunnel-missing` 拒绝，因为在他人机器上下载并执行一个联网二进制程序应由他本人决定。

**引入二维码库。** 配对码必须由已经附带的 bundle 离线绘制。编码器依据公开表格约三百行即可完成；而一个依赖意味着安装期的一次网络获取，以及此后长期的生态风险。

**用 `node-forge` 或 `pkijs` 生成证书。** 两者都要为了一个函数被引入工作区。Node 已经能签名并解析 X.509，缺的只是**写入器**，因此 DER 由手工组装，再交由 `node:crypto` 自带的解析器与一次真实 TLS 握手来裁决。

## 影响

主机头在回环这一跳会被改写，那将钝化 `client-connection` 所依赖的两道防线（DNS 重绑定、跨站）。因此边缘监听**先**自行施加它们：带有明确 `sec-fetch-site: cross-site` 标记的请求被拒绝，`Origin` 必须与设备所拨的 authority 一致。此后才替换 `Host`、`Origin`、`Cookie` 与 `Authorization`。改写永远无法把跨站请求洗白成同源请求。

审批只被观察，绝不被代答：服务在 `approval/request` 瀑布流上注册监听，并在经过时交给 `next()`，因此远程访问可以在会话进行中开启，而不改变 Harness 所问的问题，也不改变由谁作答。

已配对设备获得的是对 Harness 的完整窗口，因为它正是以桌面会话被代理的。按设备划分权限范围属于后续工作；今天唯一的粒度是吊销，而它即时且持久。

在要紧之处，验证是端到端的而非单元形态的。组合测试用真实 Loader 启动凭据、Web 服务器、`client-connection` 与静态前端，开启局域网模式，通过一条固定证书的 TLS 连接以真实二维码载荷完成设备配对，经代理取回应用，在事件流上收到由真实 `approval/request` 瀑布流产生的审批帧，并吊销该设备。证书测试用 `X509Certificate` 解析每一张签发的证书，并完成一次真实握手。二维码测试比对标准自身的容量、格式信息与对齐表，并用独立编写的解码器把每一张完成的矩阵重新读出。
