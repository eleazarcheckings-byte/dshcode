# Agent Note: SaturnBot 领域代理的持久化执行

Status: implemented

[English](2026-09-14-saturnbot-durable-specialists.md) | 中文

## Problem

自主业务工作涉及仓库编辑、消息、财务观察和外部发布。仅显示生成计划的控制台无法确认哪些操作已经执行、输出是否用于后续决策，或审批在重启后是否会重复。角色对话同样需要持久化的请求接受机制和明确的繁忙响应。

## Decision

[SaturnBot](../../../../packages/saturn/saturnbot/README.zh.md) 拥有带版本、经过 fsync 的 JSONL 执行日志，以及一个本地跨进程写入租约。类型化的规划者和领域适配器返回严格校验的 JSON。领域代理可以观察已记录的工具结果后继续执行，同时受累计操作数和模型轮数限制。每次调用工具前，根据可信适配器的角色权限上限、全局权限和角色配置进行准入检查。

开发编辑发生在托管 Git 工作树中。发布要求针对精确暂存版本成功运行已配置检查。持久化审批绑定该版本和精确操作，并在发布前标记为已消耗。活跃执行或等待审批期间不能修改普通设置。有意修改的启动 YAML 策略会中断待审批工作。重启不会自动重放中断操作；结果不确定的外部副作用需要操作者检查。

模型由现有 LLM 服务提供。调用提供方前，精确请求上下文写入辅助 Session；随后记录公开输出、用量或终止错误。执行日志保留计划、提案、结果、状态变化和角色消息，不包含私有思维链。SQLite 保存长期记忆、支持工单以及经过身份验证和去重的 Webhook 回执。周期报告形成每日 Markdown 汇总并投递至持久化收件箱。

Host 拥有调度器和执行引擎的销毁生命周期。暂停会停用后续周期而不中止已接受的工作；取消和关闭会等待活跃适配器结束。调度器根据持久化周期时间计算下次尝试，最多补执行一次逾期周期，并且仅在 Host 存活期间运行。

## Alternatives considered

仅从聊天消息重建操作状态会使审批消耗和中断副作用含糊不清。将所有超时都视为可重试，可能重复发送邮件或发布内容。为整个任务只生成一次提案，会阻止文件读取结果影响后续编辑。持久化操作位置、显式重试声明和有界继续执行直接处理了这些情况。

托管队列或操作系统守护进程可以在当前 Host 生命周期之外调度，但需要本地插件范围以外的部署、租户和凭据所有权管理。Git 工作树能够隔离仓库编辑，却不能限制 Host 账户；子进程验证仍拥有该账户的文件系统和网络权限。运行时明确说明这一限制，不声称提供沙箱。

## Consequences

无需凭据的行为测试覆盖角色提权拒绝、状态评估、有界读取与决策执行、精确版本验证、单次审批、重启恢复、并行分支失败、日志损坏、缓存不可变性、消息接受和等待取消完成。真实 Host 组合在调用模型前记录请求，并重放持久化结果；适配器测试使用真实 Git、托管子进程、文件和 SQLite，HTTP 提供方采用脚本响应。用户可见的对话投影使用快照测试。

日志与提供方 API 属于独立持久化系统。无法仅凭网络响应或崩溃推断恰好一次投递，因此不安全副作用不会重试。历史和托管工作树需要显式离线保留管理；所有权锁格式错误时拒绝继续。独立运行时目录提供独立状态，不协调外部账户或仓库。资源限制在接受副作用前拒绝超限提案，并明确报告日志容量耗尽。
