# Agent Note: SaturnBot runtime Mars fix round — deploy-hook secret lane, effort validation, Shopify domain

Status: implemented

English | [中文](2026-09-15-saturnbot-runtime-mars-fix-round.zh.md)

## Problem

A fresh-context Mars review of `packages/saturn/saturnbot` (`@saturnai/dsh-saturnbot`, SPEC §3 C8a) returned REVISE with four required fixes: (1) a configured Vercel/Cloudflare Pages deploy-hook URL — the cell's own documented secret — was accepted as a literal `endpoint` config value and therefore durably journaled in plaintext by `store.ts`'s `writeConfiguration()`, violating the ACCEPTANCE line "no secret ever appears in the journal"; (2) `LoggedBotModel.resolveRoute()` forwarded a connected model router's `reasoningEffort` straight into `ctx.llm.stream` with no validation against the target model's declared capabilities, so a router resolving an effort the configured model does not support hard-failed every planner/specialist call, contradicting `contracts.ts`'s own documented fallback contract; (3) the only new externally-sending path (`reportChannel: telegram`) had zero test coverage; (4) the Shopify `resource` (store domain) was interpolated unvalidated into the request host, and the pinned Admin API version (`2025-01`) was outside Shopify's ~12-month support window as of 2026-09-15.

## Decision

**Fix 1 — the deploy-hook URL now resolves only through `endpointEnv`, never a literal `endpoint`.** A new `endpointEnv` field (validated the same way `credentialEnv` is: `/^[A-Z_][A-Z0-9_]*$/`) was added to the integration schema in [config.ts](../../../../packages/saturn/saturnbot/src/config.ts) and [types.ts](../../../../packages/saturn/saturnbot/src/types.ts). A `superRefine` rejects a literal `endpoint` on `vercel`/`cloudflare-pages` at the schema layer — the same layer `engine.configure()` and `store.writeConfiguration()` both call `parseBotConfig` through — so a literal hook URL is refused before it can ever be journaled, not merely redacted afterward. `deployHook()` in [shared.ts](../../../../packages/saturn/saturnbot/src/adapters/shared.ts) mirrors the same refusal defensively (defense in depth for a config object constructed outside the schema) and resolves the URL from `options.environment`/`.env` via `endpointEnv`. Both `redact()` (shared.ts) and the engine's own `redacted()` ([engine.ts](../../../../packages/saturn/saturnbot/src/engine.ts)) now also scrub `endpointEnv`-sourced values, so a provider that happens to echo the hook URL back in its own response still never reaches retained tool facts. `wizard.ts`'s catalog marks the vercel/cloudflare-pages field `secret: true` with the `endpointEnv` name instead of a non-secret `endpoint` field, so C8b's generated form will never render it back.

**Fix 2 — a router-resolved reasoning effort is validated before dispatch, and dropped rather than left to hard-fail.** `resolveRoute()` in [model.ts](../../../../packages/saturn/saturnbot/src/model.ts) is now async: when a resolved route carries a `reasoningEffort`, it calls the existing `ctx.llm.resolveCallConfig({ provider, model, reasoningEffort }, signal)` (the same capability-preflight `packages/acp/acp` and `packages/subagent/tool-subagent` already use) before returning the route; an `UNSUPPORTED_REASONING_EFFORT` (or any other) failure drops just the `reasoningEffort` field, keeping the resolved `provider`/`model` — matching the fallback contract `contracts.ts` already documented for an absent or throwing router, now extended in its docblock to name this case explicitly.

**Fix 3 — the telegram report-channel path is now covered end to end.** New tests: a mocked-fetch unit test for `createReportDeliveries().telegram` (posts the digest, and a delivery failure never contains the token) in `adapters.spec.ts`; an engine-level test asserting a registered delivery is actually invoked on cycle settlement and an unregistered channel name only alerts, plus a delivery-throws case that still keeps the inbox report, in `engine.spec.ts`; and `composition.spec.ts` now asserts the real `SaturnBotService.snapshot()` projection carries `firstRun`/`integrationCatalog` (this held already — the gap was coverage, not behavior).

**Fix 4 — Shopify's store domain is validated, and the API version is current.** `shopify()` in [integrations.ts](../../../../packages/saturn/saturnbot/src/adapters/integrations.ts) now requires `resource` to match `/^[a-z0-9][a-z0-9-]*\.myshopify\.com$/u` before constructing any request URL, rejecting a mistyped or hostile domain with `ActionRequiredError` before the Admin token is ever sent anywhere; `describeBotConnections()` gained the matching pre-dispatch status check. The pinned Admin API version moved from `2025-01` to `2026-07` (Shopify supports each release ~12 months; `2026-07` is current as of 2026-09-15 and the comment names when to revisit).

**Incidental — the README had no Summary/Table of Contents/Dev Note at all.** Running the repo's own `doc-quick` gate (not merely the narrower verification scripts the original round ran) found `packages/saturn/saturnbot/README.md`/`README.zh.md` were the only 2 of 652 package READMEs in the whole repository missing YAML frontmatter and the canonical Summary/TOC/Dev Note skeleton required by `scripts/doc-standard.spec.ts`. Both files were restructured to the skeleton every sibling package already carries (anchors kept English-slug even on the Chinese side, matching the pairing convention `model-router`'s README already established, since the bilingual-pairing check compares link targets positionally).

## Alternatives considered

**Redact the deploy-hook URL after the fact instead of refusing it at the schema layer.** Rejected: redaction-only leaves a window where the literal secret is written to the config YAML mirror and the journal before any redaction pass runs; refusing the literal value at `parseBotConfig` — the single choke point every write path already calls — closes the leak at its source rather than papering over it downstream.

**Throw when a router-resolved effort is unsupported, matching the stricter `preflightChildLlmRoute` pattern in `tool-subagent`.** Rejected: `contracts.ts` explicitly documents this router as advisory (`a router that throws or omits a field is treated as absent for that call, falling back`), and SaturnBot's own cycles are unattended background work — hard-failing every planner/specialist call because a router misconfigured one tier's effort would stall the whole business goal rather than degrade one call's routing.

**Leave the Shopify version pin at `2025-01` and only note the drift in Known Limitations.** Rejected: the README already claims shapes follow "public documentation as of 2026-09-15"; leaving a stale, unsupported version pinned while claiming currency is the kind of silent inaccuracy SPEC §6's evidence discipline exists to prevent.

## Consequences

`node_modules/.bin/vitest run packages/saturn/saturnbot` is 85/85 green (75 baseline + 10 new: 1 model-router effort-drop test, 1 wizard catalog test, 6 adapters tests — shopify-domain rejection, vercel/cloudflare-pages via `endpointEnv`, echoed-URL redaction, 2 telegram report-delivery tests — and 2 engine tests for the config-schema rejection and journal-safety, plus 2 report-channel-delivery engine tests). `tsc -p packages/saturn/saturnbot/tsconfig.json --noEmit` is clean. `npx tsx scripts/run-gates.ts doc-quick` shows zero findings under `packages/saturn/saturnbot/*`; every remaining doc-quick finding belongs to a sibling cell's files (`ui-saturnbot`, `ui-skin-saturn`, `tool-media`, `agent-presets`) or a repo-wide translation-pairing backlog predating this round, and is left for its owning cell. `config.example.yaml` was updated to the `endpointEnv` shape and still parses via `parseBotYaml`.

Known gaps unchanged from the original round and recorded in the README: only Telegram implements a live `reportChannel`; the generic `cloud.deploy` webhook target, `social.publish`, and `creative.generate`'s webhook fallback still need operator-built middleware; the Telegram/Shopify/Vercel/Cloudflare Pages adapters follow public documentation but remain unverified against a live account. `ui-saturnbot` (C8b) should mark the vercel/cloudflare-pages connect-form field `secret` per the updated `integrationCatalog` shape — reported to the orchestrator as an `integration_needs` item, since `packages/client/ui-saturnbot/**` is outside this cell's scope.
